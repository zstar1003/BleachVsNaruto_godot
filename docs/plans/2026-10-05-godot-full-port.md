# BVN 3.4 完整 Godot 移植计划

**Goal:** 移植 3.4 的全部角色、形态、援助、地图、战斗规则和模式，并复用原 UI 的像素、字体、布局和动画。

**Architecture:** 通用 SWF 导出工具提取原资源及完整时间轴；Godot 原生运行数据驱动的角色控制、攻击道具、地图与菜单。每个被导出的脚本方法建立覆盖记录，不能把忽略的方法当成已移植。UI 使用原 SWF 的元件与字体，并依据原源码坐标和时间轴重建互动。

**Tech Stack:** Godot 4.7.2 / GDScript / Python 3 / Java 17 / FFDec 26.3.0。

## 用户已确认的范围

沿用当前 3.4 素材，扩展为全部移植；UI 需要同原版完全一样。直接继续实施，不再等待重复确认。

## 执行与验收

1. 保存当前双角色开发版，建立全量导出清单与覆盖报告。
2. 提取 FighterTester 中的 title/select/fight/setting/common_ui 等嵌入 SWF；导出 UI 元件、字体、状态与坐标。逐屏对照原版截图。
3. 自动发现 fighter.xml 的全部角色和形态、assistant.xml 的全部援助以及 map.xml 的地图；导出图片、音频、标签、碰撞和脚本。
4. 扩展时间轴事件模型，保留分支、循环、延迟、临时数据、子动画、矩阵及攻击道具控制。为未实现的语义记录可见缺口。
5. 还原原生战斗：移动、跳跃、瞬步、受击、击飞倒地、护甲、防御破防、抓取、连招、气、变身、援助与换人；移植原 AI。
6. 按原版流程实现单人/双人、训练、单人闯关和组队模式；持久化设置、回合、胜负、分数与结算。
7. 每个角色/形态/援助/地图完成加载和动作验证，运行组合对战；验证所有菜单路径与设置，再导出 Mac 应用。
8. 用原 AIR 3.4 作视觉、动作和输入基准；通过前不得称为完全一样或完整完成。
