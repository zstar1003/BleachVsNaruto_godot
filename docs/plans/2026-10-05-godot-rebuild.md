# Godot 3.4 双角色重构计划

**Goal:** 用 Godot 原生运行一护和鸣人的对战，随后逐项校准 3.4 的完整招式和手感。

**Architecture:** 导出原版 SWF 的动画、音效、帧标签和角色脚本，保留来源记录；Godot 以数据驱动的帧状态机处理移动、攻击、碰撞、气、防御和回合。游戏与原 AIR 工程分别保存，可独立启动。

**Tech Stack:** Godot 4.7.2 / GDScript / Python 3 / JPEXS FFDec / 原版 3.4 素材。

## 已确定的设计

优先两个角色的战斗，不先扩充选人名单。原生 Godot 重写可以摆脱 Flash 运行时并维护游戏；嵌入 Flash 不构成重构，重绘素材会降低原版视觉一致性。动画与战斗规则分开，导出管线保留原始帧坐标，避免动作间抖动。逐帧核对原脚本中的攻击、受击、消耗与移动事件。

## 实施步骤

1. 核对 SWF 帧标签与角色脚本，选择可重复导出的素材管线，记录原版本与哈希。
2. 导出两角色动作、场景及声音，建立 Godot 工程、素材加载和动画预览。
3. 实现 30 Hz 战斗帧状态机；移动、跳跃、冲刺、防御、受击、连击、气、KO 和重开。
4. 将角色招式事件与碰撞数据从原脚本转为 JSON，逐项对照。未移植的动作明确记录，不能以近似招式标注为完整移植。
5. 添加双人控制和 CPU、训练模式以及动作覆盖清单。
6. 无界面检查资源和确定性战斗；Mac 实机核对画面、控制与一轮胜负。保存启动入口和已验证范围。

## 验收边界

第一轮开发先打通原素材在 Godot 中的实际战斗闭环；双角色“完整还原”需所有动作事件与原版逐项校准后才算完成。不能把这个阶段的可玩原型称为原版一模一样。
